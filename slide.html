👥 用户与场景

目标用户

校团委老师、院系志愿工作负责人

真实痛点

  • 志愿记录散落在各班 Excel，汇总要靠手工翻表 📂
  • 期末核算“谁的时长够不够”，逐人相加易漏算 ⏰
  • 报表格式不统一，反复返工 😵
我们的解法
  • 把「查询 → 统计 → 导出」三步业务接进对话
  • 通义千问自主发起 Tool Calling，工具链自动执行
  • 结果自动出图，Excel 网页内一键下载
💡 用户不需要学操作流程，说一句需求即可得到结果与报表。

🛠️ 关键能力（一）：三个业务工具

工具入参返回
🔍 query_volunteer_data start_date / end_date（必填）
project_name（可选，项目名筛选）		 records 记录数组 / error / empty
🧮 calc_total_hours records（可省略，自动取最近查询结果） 按姓名分组：总时长 + 参与次数
📤 export_volunteer_excel summary（可省略，自动取最近统计结果） filename，页面即时出现下载按钮
参数设计 1

可选参数降低表达门槛，用户不必说全条件

参数设计 2

大数组不让模型回传，工具内部取缓存，避免参数被截断

参数设计 3

统一 status / message / data 三段式返回，模型据此决策

调用链：查询 → 统计 → 导出，由模型自主串联4 / 10

🧭 思政与合规说明

数据来源
  • 全部为课程自建模拟数据，不含任何真实学生信息
  • 姓名、学号均为虚构占位（张三 / 2023001 等）
隐私保护
  • 无数据外传，仅本机运行，不接入第三方数据库
  • API Key 存 .env 并由 .gitignore 排除：不进代码、不进仓库、不进幻灯片
使用边界
  • 定位为课程演示原型，正式使用须补：登录鉴权、数据脱敏、操作留痕
  • 统计结果仅供参考，最终认定以学校志愿管理系统原始记录为准
诚信合规
  • 工具调用由模型真实发起，未用关键词判断伪造 Agent 能力
  • 不对模型输出“预埋答案”，数据由工具真实计算
数据合规 · 隐私保护 · 使用边界7 / 10

🧩 不足与后续改进

当前不足
  • 数据存于内存（session_state），重启即恢复样例，未接数据库
  • 单用户本地应用，无登录与多用户隔离
  • 筛选维度有限：仅日期 + 项目名，未支持姓名 / 时长区间
  • 相对时间（“本月”“上周”）依赖模型换算，极端表述需补具体日期
后续改进
  • 💾 接入 SQLite / 云数据库，记录持久化并支持多端
  • 🔒 增加登录与审核流：提交—审核—归档，导出加确认
  • 🧰 扩展工具：个人明细、月度趋势图、催报提醒
  • 🐳 Docker 部署，对接学校志愿管理系统真实 API
不足与后续改进9 / 10
