04 · 代码讲解 ①

核心循环：模型只决定调谁，代码负责真干

run_agent() 一次请求最多 6 轮：模型给工具名与参数，本地执行后把结果回填，再让模型继续判断
app.py · run_agent() · 节选
for _ in range(6): # ① 轮次上限，防失控 resp = client.chat.completions.create( model=MODEL_NAME, messages=messages, tools=TOOLS_SCHEMA, temperature=0.3) msg = resp.choices[0].message if msg.tool_calls: # ② 模型决定调哪个工具 messages.append({"role": "assistant", "tool_calls": normalized_calls}) for name, args, call_id in parsed_calls: result = execute_tool(name, args) # ③ 本地真实执行 messages.append({"role": "tool", # ④ 结果回填 "tool_call_id": call_id, "content": json.dumps(result, ensure_ascii=False)}) continue # ⑤ 带着结果再问模型 history.append(("assistant", msg.content)) # ⑥ 自然语言收尾 return
①轮次上限 6
防止模型反复调工具停不下来；超限给出明确提示并可重试
②决策权在模型
代码里没有 if "统计" in text 这类关键词分支，调不调、调几次由 tool_calls 决定
③执行权在代码
execute_tool 是本地真实函数：pandas 筛选、openpyxl 写文件，结果可复现
④回填形成闭环
role=tool 的消息带 tool_call_id，模型下一轮才能"看到"真实结果
参数不合法（JSON 截断）时先规范化再回填，避免下一轮请求 400
6 轮 · 调用上限
单次请求最多循环 6 次，防模型原地打转
3 次 · 典型调用数
“查询 → 统计 → 导出”链路各调一次工具
0 处 · 关键词分支
代码不判断“统计/导出”等字样，决策权完全交给模型

05 · 代码讲解 ②

工具怎么写：一份 JSON Schema + 一道校验关

Schema 决定模型"能不能填对"，校验决定"填错了会不会炸"——两侧都要设计
TOOLS_SCHEMA · add_volunteer_record
{"type": "function", "function": { "name": "add_volunteer_record", "description": "为当前绑定账号登记一条志愿记录", "parameters": { "type": "object", "properties": { "project_name": {"type": "string"}, "hours": {"type": "number"}, "date": {"type": "string", # YYYY-MM-DD "description": "缺省=今天"} }, "required": ["project_name", "hours"] }}}
add_volunteer_record() · 校验
if d > date.today(): return {"status": "error", ...} if not 0 < h <= 24: return {"status": "error", ...} if dup.shape[0]: return {"status": "error", ...}
①必填只留两个
活动名 + 时长是用户一定会说的；日期、地点可不给
②身份不进参数
姓名学号取自绑定账号 bound_account，模型无权填写，杜绝张冠李戴
③三类硬校验
日期格式与未来日期、时长区间 0<h≤24（统一到 0.5 刻度）、同人同日重复记录
④错误说人话
返回 status=error + 具体原因，模型据此向用户解释并请求修正，页面不崩溃
返回结构：{status, record, personal_total}
模型拿 personal_total 直接回答“本人累计 18.5 小时”，不必自己加总
参数设计的检验标准：模型第一次就能填对（描述清楚、必填最少）；填错时程序能拦住并说清原因（校验有边界、错误可读）。

06 · 代码讲解 ③

换账号时，卡片、明细、对话一起换

switch_account() 是唯一切换入口：先换身份，再清缓存；顶部四张卡片始终是"本人数据的实时派生"，总时长 = 校内 + 校外
app.py · switch_account() / render_stats()
def switch_account(acc): bound_account = dict(acc) if acc else None show_all_rows = False # 回到只看本人 reset_record_views() # 清空查询/统计/导出/对话 def render_stats(): # 四张卡 = 本人数据 mine = my_records_df() # df[df.姓名 == 绑定账号] on = mine[mine.类型 == "校内"]["时长(小时)"].sum() off = mine[mine.类型 == "校外"]["时长(小时)"].sum() n, total = len(mine), on + off # 总时长 = 校内 + 校外 if clicked(): # 点卡片 → 展开明细 show_my_records = True st.rerun()
明细面板 data 直接来自 my_records_df()：录入一条新记录，卡片数字、明细表、账号条在同一轮渲染里一起变
①唯一入口
绑定、切换、退出都走这一个函数，避免多处各写 session_state 导致不同步
②缓存一起清
last_records / last_summary / excel_file / history 全清，防止拿上一账号的结果回答
③卡片是派生值
不额外存一份统计，直接由 df 过滤求和——所以永远实时；总时长恒等于校内 + 校外，三个数字不会互相打架
④点开即下钻
点「志愿记录总数」整卡展开逐条明细（日期/项目/类型/时长/地点/备注），可按全部 / 校内 / 校外切换
切换前 · 张三
4 条 · 总 15.5h（校内 12.5 / 校外 3.0）　对话 3 轮
切换后 · 李四
2 条 · 总 8.5h（校内 2.5 / 校外 6.0）　对话已清空
再录一条 · 张三
卡片立刻变 5 条 · 总 18.5h（校外 +3），明细同步多一行
为什么强调「唯一入口」：Streamlit 每次交互都会重跑整个脚本，st.session_state 是唯一的事实来源；若在多个按钮里各写一份绑定逻辑，卡片、明细、对话就会出现“换了一半”的不一致。

取舍一 · 可选参数
用户不必说全条件，模型可采用默认行为
取舍二 · 数据不回传
统计与导出省略数组参数，避免长 JSON 被截断导致 400
取舍三 · 状态三值
success / empty / error 让模型分别给出结果、提示或修正建议
取舍四 · 距离不由模型算
距离排序交给 Haversine 公式；同城才排、跨市改按日期，sort_by 告诉模型该怎么说
取舍五 · 身份不进参数
姓名学号取自绑定账号，模型无需询问也无权填写，避免张冠李戴
取舍六 · 分项拆成独立工具
calc_hours_by_type 一次给出校内 / 校外 / 总计，不让模型先查再自己相加

13 · 合规说明

数据来源、隐私与使用边界

演示效果让位于合规：不使用真实学生信息，不在交付物中出现密钥
数据来源
志愿记录与姓名学号为课程自建模拟数据；省市区县与高校名单来自公开开源数据集（MIT/公开许可）；仅存于本机内存
隐私与密钥
密钥存 .env 并由 gitignore 排除；代码、仓库、幻灯片中均不含真实 Key
使用边界
课程演示原型，不作正式认定依据；活动条目为模板生成的演示内容，报名以主办方公告为准
学术诚信
工具调用由模型真实发起，未用关键词判断伪造能力；数据由工具真实计算，无预埋答案
位置信息：仅使用公开的校区经纬度估算活动直线距离（331 所无公开坐标的高校用所在城市中位数兜底），不采集、不存储用户实时定位；跨市查询不计算距离。
统计结果最终以学校志愿管理系统的原始记录为准；本工具用于减轻重复劳动，不替代认定流程。
