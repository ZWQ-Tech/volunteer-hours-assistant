# ⏱️ 校园志愿时长汇总助手（路径 B）

> 课程：《开源AI技术实践》期末考察项目 · 路径 B
> 一句话场景：把"查志愿记录 → 统计总时长 → 导出 Excel"和"看校内活动 → 找校外附近活动"两条业务，全部交给自然语言对话完成，由通义千问 Tool Calling 驱动。

---

## 1. 项目介绍

校园志愿活动多、记录分散，期末统计"谁的志愿时长够不够"往往靠手工翻 Excel，活动信息又散落在公众号和班级群里。本项目把这套流程封装成一个 **Streamlit Web 应用 + LLM Agent**：

- 用户在对话框说一句"帮我统计 10 月每个人的志愿总时长，并导出 Excel"；
- 通义千问解析意图，自主决定依次调用查询工具、统计工具、导出工具（链式 Tool Call）；
- 页面实时高亮展示每一次工具调用的入参/结果日志，查询后自动生成柱状图，导出的 Excel 直接在网页内点击下载；
- 用户绑定学校后，页面可展示校内志愿活动的实时更新，并按距离推送校园周边的校外活动，同样支持自然语言查询。

工具调用全部通过 Function Calling 协议由模型真实发起；四个业务工具均为本项目自主设计实现。

### 场景说明

| 项目 | 说明 |
| --- | --- |
| 选题 | 志愿服务｜社区志愿活动分配与时长统计 |
| 目标用户 | 校团委/院系志愿者负责人、班级志愿委员 |
| 痛点 | 志愿记录散落在各班表格里，汇总、校对、出报表全靠手工；活动信息分散在公众号与群通知中 |
| 方案价值 | 自然语言一句直达，工具链自动执行，结果可视化、可下载留档；绑定学校后可集中查看校内实时活动与校外推送 |

### 技术栈

| 层 | 技术 | 用途 |
| --- | --- | --- |
| 大模型 | 通义千问（`qwen-plus`，可通过 `.env` 的 `DASHSCOPE_MODEL` 切换为 `qwen-turbo` 等） | 意图理解、Tool Call 决策 |
| 接入方式 | OpenAI 兼容接口（`openai` SDK） | 无缝切换其他兼容模型 |
| Web 框架 | Streamlit | 对话界面、表单、图表、日志分区 |
| 数据处理 | pandas | 记录筛选、按姓名分组统计 |
| 图表可视化 | plotly.express | 柱状图展示每人累计时长 |
| Excel 导出 | openpyxl | 生成 xlsx 汇总表 |
| 活动推送 | Streamlit 会话态轮询 + Haversine 距离公式 | 校内活动实时刷新、校外活动按距离排序 |
| 密钥管理 | python-dotenv | `.env` 加载 API Key，不入库 |

### 主要功能特性

1. **绑定学校**：侧栏选择并绑定学校（内置 4 所院校的校区与经纬度），绑定后顶部出现学校状态条，展示"校内活动数 / 校外活动数 / 最近活动距离"。
2. **活动中心（实时刷新 + 校外推送）**：页面底部分「校内活动」「校外活动」两个页签。校内活动按更新时间轮询刷新（报名人数递增、新活动推入并高亮 NEW 标记）；校外活动按与校园的直线距离排序，可用滑杆调整推送半径（1–20 km），每张卡片显示距离、主办方、时段、报名进度。
3. **日志分区展示**：独立区域高亮显示每一次工具调用的工具名、入参、状态、结果摘要，与模型对话内容明确区分。
4. **网页内置 Excel 下载按钮**：导出成功后侧栏即时出现下载按钮，一键保存，无需去文件夹找文件。
5. **新增记录表单**：侧栏表单可向模拟数据表追加志愿记录（姓名/学号/项目/日期/时长），形成"写入-查询"闭环。
6. **异常容错**：日期格式校验、结束日期不得早于起始日期、无数据友好提示、未绑定学校时的引导提示、工具异常统一捕获，程序不崩溃。
7. **自动柱状图**：每次统计成功后，plotly 柱状图自动展示每人累计时长。

## 2. 运行步骤（Windows 可直接复制执行）

```bash
# 1. 进入项目目录
cd volunteer-hours-assistant

# 2. 创建并激活虚拟环境
python -m venv .venv
.venv\Scripts\activate

# 3. 安装依赖
pip install -r requirements.txt

# 4. 配置密钥：复制 .env.example 为 .env，填入你的 DashScope API Key
copy .env.example .env

# 5. 启动
streamlit run app.py
```

启动后浏览器自动打开 `http://localhost:8501`。

使用顺序：① 左侧栏顶部「绑定学校」选择学校 → ② 页面底部「活动中心」浏览校内/校外活动 → ③ 在对话框用自然语言发起查询、统计、导出；右侧栏可新增志愿记录。

## 3. 核心工具参数说明

### 3.1 `query_volunteer_data` —— 按条件查询志愿记录

| 项 | 内容 |
| --- | --- |
| 入参 `start_date` | `string`，必填，格式 `YYYY-MM-DD`，起始日期 |
| 入参 `end_date` | `string`，必填，格式 `YYYY-MM-DD`，结束日期 |
| 入参 `project_name` | `string`，**可选**，志愿项目名称关键字筛选（如"图书馆"） |
| 返回（成功） | `{"status": "success", "count": n, "message": "...", "records": [{姓名, 学号, 志愿项目, 日期, 时长(小时)}, ...]}` |
| 返回（异常） | `{"status": "error", "message": "日期格式不正确..."}` / `{"status": "error", "message": "结束日期早于起始日期..."}` |
| 返回（无数据） | `{"status": "empty", "message": "该时间段没有查询到志愿记录"}` |

参数设计说明：`project_name` 设为可选参数，扩大模型可用表达空间；日期在工具内部做二次校验，不信任模型输出的格式。

### 3.2 `calc_total_hours` —— 按姓名分组统计累计时长

| 项 | 内容 |
| --- | --- |
| 入参 `records` | `array<object>`，**可选**，来自上一次查询的 `records`；省略时自动使用最近一次查询结果（体现工具链式调用） |
| 返回（成功） | `{"status": "success", "summary": [{姓名, 总时长(小时), 参与次数}], "总计(小时)": x}` |
| 返回（异常） | `{"status": "empty"...}`（无记录可统计）/ `{"status": "error", "message": "缺少字段..."}` |

参数设计说明：`records` 设计为可省略，工具内部直接读取会话中缓存的最近一次查询结果，避免让模型把大数组原样回传导致参数 JSON 被截断；字段缺失、非数值时长均做容错（`fillna(0)`、`to_numeric(errors="coerce")`），统计结果按总时长降序，便于生成排名式回答。

### 3.3 `export_volunteer_excel` —— 导出汇总 Excel

| 项 | 内容 |
| --- | --- |
| 入参 `summary` | `array<object>`，**可选**，来自上一次统计的 `summary`；省略时自动使用最近一次统计结果 |
| 返回（成功） | `{"status": "success", "filename": "志愿时长汇总_20261026_195300.xlsx", "message": "..."}` |
| 返回（异常） | `{"status": "empty"...}`（无可导出数据）/ `{"status": "error", "message": "导出失败：..."}` |

参数设计说明：`summary` 同样可省略，工具内部读取最近一次统计结果，避免大数组回传；生成 xlsx 二进制后写入会话状态，页面侧栏随即出现内置下载按钮；文件名带时间戳避免覆盖。

### 3.4 `query_open_activities` —— 查询校内/校外志愿活动

| 项 | 内容 |
| --- | --- |
| 入参 `scope` | `string`，**可选**，枚举 `all` / `on_campus` / `off_campus`，默认 `all`；用户只问校内就传 `on_campus`，只问附近就传 `off_campus` |
| 入参 `radius_km` | `number`，**可选**，校外活动推送半径（公里），默认 `5.0`；用户说"周边 3 公里"时由模型换算填入 |
| 入参 `keyword` | `string`，**可选**，标题/主办/地点/标签关键字，如"图书馆""环保" |
| 返回（成功） | `{"status": "success", "school": "江城大学（本部）", "on_campus": [...], "off_campus": [...], "message": "..."}` |
| 返回（未绑定） | `{"status": "error", "message": "尚未绑定学校，请先在左侧绑定学校后再查询活动"}` |
| 返回（无匹配） | `{"status": "empty", "message": "该范围内没有符合条件的活动"}` |

返回结构说明：每条活动含 `标题 / 主办 / 地点|地址 / 日期 / 时间段 / 时长 / 名额 / 已报名 / 标签 / 更新时间`，校外活动额外带 `距离(km)`，列表按距离升序，便于模型直接回答"哪个最近"。

参数设计说明：三个参数全部可选，因此模型可以只传一个 `scope`，也可以一句话带出"校内 2 公里内环保类活动"这种复合意图；距离由工具内的 Haversine 公式计算，不让模型自己算，避免数值幻觉。未绑定学校时工具主动返回 `error` 引导用户绑定，而不是编造数据。

### 调用链

`query_volunteer_data` → `calc_total_hours` → `export_volunteer_excel`

`query_open_activities`（活动咨询独立分支，可与时长统计链并行）

模型依据系统提示词与工具描述自主串联这些工具，无需人工编排。查询、统计、导出、活动查询四个状态（success / error / empty）均以结构化 JSON 返回，由模型根据状态决定下一步动作或向用户转述结果。

### 对话示例

| 用户输入 | 模型自主发起的工具调用 |
| --- | --- |
| 帮我统计 10 月每个人的志愿总时长并导出 Excel | `query_volunteer_data` → `calc_total_hours` → `export_volunteer_excel` |
| 这周学校有哪些志愿活动可以报名 | `query_open_activities(scope="on_campus")` |
| 学校附近 3 公里内有没有环保类的活动 | `query_open_activities(scope="off_campus", radius_km=3, keyword="环保")` |
| 图书馆那个项目我做了多少小时 | `query_volunteer_data(start_date=..., end_date=..., project_name="图书馆")` |

## 4. 局限与后续规划

### 当前局限

- 数据为内存模拟数据（`st.session_state`），重启即恢复初始样例，未接数据库；表单新增的记录、已绑定学校只保存在当前会话中。
- 单用户本地应用，未做多用户并发、登录鉴权与会话隔离。
- 仅支持按日期+项目名筛选，暂不支持按姓名、时长区间等复合条件查询。
- 活动数据为内置模拟数据 + 本地定时器模拟刷新，非真实校方系统接口；校外活动按直线距离（Haversine）估算，未接入地图路网导航。
- 导出工具的文件字节暂存于会话状态，未做历史导出记录管理。
- 模型换算相对时间（"本月""上周"）依赖模型能力，极端表述可能需要用户补充具体日期。

### 后续扩展规划

1. **数据持久化**：接入 SQLite/云数据库，新增记录、绑定学校、报名状态长期保存，支持多端访问。
2. **权限与审批**：志愿时长"提交—审核—归档"流程化，导出操作加确认步骤。
3. **工具扩展**：新增"按姓名查询个人明细""生成月度趋势折线图""发送催报提醒""活动报名"等工具。
4. **真实活动源**：对接校团委志愿管理系统或公众号接口，把模拟活动池换成实时抓取，并接入地图路线规划 API 计算真实通勤距离。
5. **部署**：Docker 化部署至服务器，支持更大并发。
