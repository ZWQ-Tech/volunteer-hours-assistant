# ⏱️ 校园志愿时长汇总助手（路径 B）

> 课程：《开源AI技术实践》期末考察项目 · 路径 B
> 一句话场景：把"查志愿记录 → 统计总时长 → 导出 Excel"和"看校内活动 → 找校外附近活动"两条业务，全部交给自然语言对话完成，由通义千问 Tool Calling 驱动。

---

## 1. 项目介绍

校园志愿活动多、记录分散，期末统计"谁的志愿时长够不够"往往靠手工翻 Excel，活动信息又散落在公众号和班级群里。本项目把这套流程封装成一个 **Streamlit Web 应用 + LLM Agent**：

- 用户在对话框说一句"帮我统计 10 月每个人的志愿总时长，并导出 Excel"；
- 通义千问解析意图，自主决定依次调用查询工具、统计工具、导出工具（链式 Tool Call）；
- 页面实时高亮展示每一次工具调用的入参/结果日志，查询后自动生成柱状图，导出的 Excel 直接在网页内点击下载；
- 页面把志愿时长拆成**校内 / 校外 / 总计**三个口径，总时长用一张深色渐变的大卡片单独突出；
- 用户绑定学校（全国 1300+ 所本科高校，按省 → 市 → 校三级选择）后，可看校内志愿活动；校外活动支持**全国 34 个省级行政区、368 个城市、3078 个区县**逐级筛选。

工具调用全部通过 Function Calling 协议由模型真实发起；六个业务工具均为本项目自主设计实现。

### 场景说明

| 项目 | 说明 |
| --- | --- |
| 选题 | 志愿服务｜社区志愿活动分配与时长统计 |
| 目标用户 | 校团委/院系志愿者负责人、班级志愿委员 |
| 痛点 | 志愿记录散落在各班表格里，汇总、校对、出报表全靠手工；活动信息分散在公众号与群通知中 |
| 方案价值 | 自然语言一句直达，工具链自动执行，结果可视化、可下载留档；校内 / 校外时长分开统计且总计醒目；绑定学校后可看校内活动，校外活动可按全国任意省市区县查询，并查看详情、跳转官方报名 |

### 技术栈

| 层 | 技术 | 用途 |
| --- | --- | --- |
| 大模型 | 通义千问（`qwen-plus`，可通过 `.env` 的 `DASHSCOPE_MODEL` 切换为 `qwen-turbo` 等） | 意图理解、Tool Call 决策 |
| 接入方式 | OpenAI 兼容接口（`openai` SDK） | 无缝切换其他兼容模型 |
| Web 框架 | Streamlit | 对话界面、表单、图表、日志分区、活动详情展开 |
| 数据处理 | pandas | 记录筛选、按姓名分组统计、校内校外双维度汇总 |

| Excel 导出 | openpyxl | 生成 xlsx 汇总表 |

### 主要功能特性

1. **个人账号绑定与记录联动**：侧栏顶部可绑定个人账号（内置 4 个演示账号：张三/李四/王五/赵六，也可「新建我的账号」填写姓名+学号+院系）。绑定后顶部状态条显示"我的记录数 / 我的总时长 / 校内时长 / 校外时长"；页面上方固定**四张 KPI 卡片**（从左到右）——「**累计志愿总时长**」「校内志愿时长」「校外志愿时长」「我的志愿记录总数」。最左侧的总时长卡占最大宽度，采用深蓝渐变、42px 大字号与阴影单独突出，卡内附校内 / 校外占比条，视觉权重明显高于其余三张；**点击最右侧的记录总数卡片即可展开逐条记录明细**（日期 / 项目 / 类型 / 时长 / 地点 / 备注，可按全部 / 校内 / 校外切换），再点「收起明细」收起；后续录入志愿记录只需填活动名称与时长，姓名与学号由账号自动带入。
   **切换账号时记录同步切换**：四张 KPI 卡片与明细面板、数据表、对话查询结果、统计表、柱状图、导出文件名全部跟着新账号走，且在录入新记录后即时刷新；切换瞬间即清空上一个账号的查询结果与对话上下文，数据表模式为"仅本人"，勾选「显示全部成员的记录」或对助手说"每个人/全员"才切到全员口径（KPI 卡片始终保持本人数据）。
2. **校内外时长分开统计**：每条记录带「类型」字段（校内 / 校外），页面 KPI、明细面板、统计表、柱状图与对话查询结果统一按"校内 / 校外 / 总计"三口径呈现；对话里问"校内多少、校外多少、总共多少"由新增的 `calc_hours_by_type` 工具一次返回三个数。旧会话数据在启动时由 `migrate_df()` 自动补齐缺失列，不会因新增字段报错。
3. **绑定学校（全国高校）**：侧栏按 ① 省份 → ② 城市 → ③ 搜索校名 → ④ 选择学校 四级选择，内置 **1308 所本科高校**（覆盖 31 个省级行政区 + 港澳台），带真实校区地址与经纬度，默认绑定上海杉达学院金海校区；绑定后活动地区自动同步到学校所在省市区，顶部状态条展示"校内活动数 / 当前活动地区 / 覆盖区数 / 最近活动距离"。
4. **活动中心（全国省市区三级筛选 + 校内外分开）**：页面底部用「省份 / 直辖市 / 自治区」→「城市」→「区县」三个下拉框逐级定位（34 省 / 368 市 / 3078 区县），再配合「全部 / 校内 / 校外」范围切换与关键字搜索；顶部一条面包屑实时显示"当前范围 · 地区 · 关键字 · 共 N 个（校内 X / 校外 Y）"，另有一键「↩️ 回到本校」按钮。校内活动按轮询刷新（报名人数递增、新活动推入并高亮 NEW）；校外活动按所选地区稳定生成，同城按距校区距离排序、跨市自动改为按日期排序并在标题处说明。
5. **活动详情与报名入口**：每张卡片下方可展开「活动详情与报名」，查看活动介绍、招募对象、集合信息、联系人、注意事项，并附官方平台报名链接（上海志愿者网 / 上海科技馆 / 上海图书馆 / 中华艺术宫 / 上海市血液中心 / 学校官网），一键跳转报名。
6. **日志分区展示**：独立区域高亮显示每一次工具调用的工具名、入参、状态、结果摘要，与模型对话内容明确区分。
7. **网页内置 Excel 下载按钮**：导出成功后侧栏即时出现下载按钮，一键保存，无需去文件夹找文件。
8. **一键录入志愿记录**：侧栏表单只需「活动名称 + 服务日期 + 时长（+可选地点）」即可写入当前账号名下，类型留空时按活动名自动判断校内 / 校外，也可直接选；既可直接点按钮提交，也可在对话里说"帮我记一笔：今天社区清洁 3 小时"，由模型调用录入工具完成，形成"写入-查询-统计-导出"闭环。
9. **异常容错**：日期格式校验、结束日期不得早于起始日期、未来日期拒绝登记、重复记录提示、单次时长超范围提示、无数据友好提示、未绑定账号/学校时的引导提示、非法省市区县返回可选项而不是空结果、工具异常统一捕获，程序不崩溃。
10. **自动柱状图**：每次统计成功后，plotly 柱状图自动展示每人累计时长，有校内 / 校外数据时渲染为堆叠柱。

## 3. 核心工具参数说明

### 3.1 `query_volunteer_data` —— 按条件查询志愿记录

| 项 | 内容 |
| --- | --- |
| 入参 `start_date` | `string`，必填，格式 `YYYY-MM-DD`，起始日期 |
| 入参 `end_date` | `string`，必填，格式 `YYYY-MM-DD`，结束日期 |
| 入参 `project_name` | `string`，**可选**，志愿项目名称关键字筛选（如"图书馆"） |
| 入参 `scope` | `string`，**可选**，枚举 `me` / `all`，默认 `me`。`me` 只查当前登录账号本人的记录（与页面记录口径一致），`all` 查全部成员；用户说"每个人/全员/全班"时由模型传 `all` |
| 入参 `kind` | `string`，**可选**，枚举 `校内` / `校外`，默认空（不限）。用于"我校内做了哪些""校外活动记录给我看看"这类只关心单侧口径的问题 |
| 返回（成功） | `{"status": "success", "scope": "me", "owner": "张三（本人）", "count": n, "message": "...", "records": [{姓名, 学号, 志愿项目, 类型, 日期, 时长(小时)}, ...], "分类合计(小时)": {"校内": x, "校外": y, "合计": z}}` |
| 返回（异常） | `{"status": "error", "message": "日期格式不正确..."}` / `{"status": "error", "message": "结束日期早于起始日期..."}` |
| 返回（无数据） | `{"status": "empty", "owner": "张三（本人）", "message": "张三（本人）在该时间范围内没有志愿记录"}` |

参数设计说明：`project_name`、`scope`、`kind` 均为可选参数，扩大模型可用表达空间；日期在工具内部做二次校验，不信任模型输出的格式。`scope` 让"我的记录"与"全员记录"两种业务口径并存——个人账号切换后，默认口径自动跟着变，避免出现"页面显示我的记录、对话却报全班数据"的不一致。返回里固定附带 `分类合计(小时)`，模型回答"这些记录里校内校外各多少"时不必再调一次统计工具。

### 3.2 `calc_total_hours` —— 按姓名分组统计累计时长

| 项 | 内容 |
| --- | --- |
| 入参 `records` | `array<object>`，**可选**，来自上一次查询的 `records`；省略时自动使用最近一次查询结果（体现工具链式调用） |
| 返回（成功） | `{"status": "success", "summary": [{姓名, 总时长(小时), 参与次数, 校内(小时), 校外(小时)}], "总计(小时)": x, "校内(小时)": y, "校外(小时)": z}` |
| 返回（异常） | `{"status": "empty"...}`（无记录可统计）/ `{"status": "error", "message": "缺少字段..."}` |

参数设计说明：`records` 设计为可省略，工具内部直接读取会话中缓存的最近一次查询结果，避免让模型把大数组原样回传导致参数 JSON 被截断；字段缺失、非数值时长均做容错（`fillna(0)`、`to_numeric(errors="coerce")`），统计结果按总时长降序，便于生成排名式回答。汇总时同时给出每人的校内 / 校外分项，回答"谁的总时长够、其中校外还差多少"不需要二次查询。

### 3.3 `calc_hours_by_type` —— 校内 / 校外 / 总计三口径汇总（新增）

| 项 | 内容 |
| --- | --- |
| 入参 `scope` | `string`，**可选**，枚举 `me` / `all`，默认 `me`；口径规则与 `query_volunteer_data` 一致 |
| 入参 `start_date` | `string`，**可选**，`YYYY-MM-DD`，省略则不限起点 |
| 入参 `end_date` | `string`，**可选**，`YYYY-MM-DD`，省略则不限终点 |
| 返回（成功） | `{"status": "success", "owner": "张三（本人）", "校内(小时)": 12.5, "校外(小时)": 3.0, "总计(小时)": 15.5, "占比": {"校内": "80.6%", "校外": "19.4%"}, "校内项目": 3, "校外项目": 1, "message": "..."}` |
| 返回（无数据） | `{"status": "empty", "message": "在指定范围内没有可统计的志愿记录"}` |

参数设计说明：单独拆出这个工具而不是往 `calc_total_hours` 里加参数，是因为"我的校内校外各多少、总共多少"是最高频的一句话意图——一次调用直接拿到三个口径与占比，模型不必先查询再自己相加（自算容易产生数值幻觉）。`start_date` / `end_date` 可选，支持"这学期校内做了多少小时"这类带时间范围的追问。

### 3.4 `export_volunteer_excel` —— 导出汇总 Excel

| 项 | 内容 |
| --- | --- |
| 入参 `summary` | `array<object>`，**可选**，来自上一次统计的 `summary`；省略时自动使用最近一次统计结果 |
| 返回（成功） | `{"status": "success", "filename": "志愿时长汇总_20261026_195300.xlsx", "message": "..."}` |
| 返回（异常） | `{"status": "empty"...}`（无可导出数据）/ `{"status": "error", "message": "导出失败：..."}` |

参数设计说明：`summary` 同样可省略，工具内部读取最近一次统计结果，避免大数组回传；生成 xlsx 二进制后写入会话状态，页面侧栏随即出现内置下载按钮；文件名带时间戳避免覆盖。导出的表格同时含"总时长 / 校内 / 校外"三列。

### 3.5 `query_open_activities` —— 查询校内活动与全国任意省市区县的校外活动

| 项 | 内容 |
| --- | --- |
| 入参 `scope` | `string`，**可选**，枚举 `all` / `on_campus` / `off_campus`，默认 `all`；用户只问校内就传 `on_campus`，只问校外/某地就传 `off_campus` |
| 入参 `province` | `string`，**可选**，省级行政区全称（如"四川省""香港特别行政区"）；省略时按 `city` / `district` 反查省份，都省略则用页面当前选择 |
| 入参 `city` | `string`，**可选**，地级市（如"成都市"）；省略时按 `district` 反查所属城市 |
| 入参 `district` | `string`，**可选**，区县（如"武侯区"）；省略则返回该市全部区县的活动 |
| 入参 `keyword` | `string`，**可选**，标题/主办/地点/标签关键字，如"科普""助老""环保" |
| 返回（成功） | `{"status": "success", "school": {...}, "area": "四川省成都市武侯区", "province": "四川省", "city": "成都市", "district": "武侯区", "sort_by": "date", "on_campus": [...], "off_campus": [...], "message": "..."}` |
| 返回（未绑定） | `{"status": "error", "message": "尚未绑定学校，无法查询校内活动。请先在左侧「学校绑定」中选择并绑定学校。"}` |
| 返回（地区非法） | `{"status": "error", "message": "「上海市」下没有「成都市」。可选城市：上海市……"}` / `{"status": "error", "message": "「成都市」下没有「火星区」。可选区县：武侯区、锦江区……"}` |
| 返回（无匹配） | `{"status": "empty", "message": "「四川省成都市武侯区」范围内没有找到符合条件的活动（关键词：科普）。可以换一个区县或换关键词再试。"}` |

返回结构说明：每条活动含 `标题 / 主办 / 地点|地址 / 省份 / 城市 / 区域 / 日期 / 时间段 / 时长 / 名额 / 已报名 / 剩余名额 / 标签 / 类型 / 报名链接`；只在与校区同城时额外带 `距离km` 并据此升序排列，跨市不返回距离、改按日期排序，同时 `sort_by` 字段标明排序依据，供模型如实描述（避免出现"距上海校区 1700 km 由近到远"这种失真的说法）。

参数设计说明：五个参数全部可选，支持"浦东新区有什么科普类活动""成都武侯区有什么志愿活动""鼓楼区附近的志愿活动"等复合或省略式表达。地区解析做了三层兜底：名称归一化（"浦东"→"浦东新区"、"成都"→"成都市"）→ 缺省份时按城市/区县**反查**所属省与市 → 仍失败则退回页面当前选择；非法地区直接返回可选项而不是静默返回空列表。距离由工具内的 Haversine 公式计算，不让模型自己算，避免数值幻觉。未绑定学校时工具主动返回 `error` 引导用户绑定，而不是编造数据。

### 3.6 `add_volunteer_record` —— 为自己录入新的志愿记录

| 项 | 内容 |
| --- | --- |
| 入参 `project_name` | `string`，**必填**，志愿活动名称，如"社区垃圾分类督导" |
| 入参 `hours` | `number`，**必填**，本次时长（小时），如 `3`、`2.5`；超 24 小时会被拒绝 |
| 入参 `date` | `string`，**可选**，`YYYY-MM-DD`；省略则默认当天，未来日期会被拒绝 |
| 入参 `place` | `string`，**可选**，服务地点 |
| 入参 `kind` | `string`，**可选**，枚举 `校内` / `校外`；省略时按活动名关键词（图书馆 / 迎新 / 运动会 / 校园 / 实验室等）自动判断 |
| 入参 `note` | `string`，**可选**，备注 |
| 返回（成功） | `{"status": "success", "record": {...}, "personal_total": 17.0, "personal_count": 4, "message": "已为 张三（学号 2023001）录入：2026-10-27 社区垃圾分类督导 3 小时（校外）……"}` |
| 返回（未绑定） | `{"status": "error", "message": "尚未绑定个人账号。请先在左侧「个人账号」中选择或新建账号并绑定……"}` |
| 返回（重复） | `{"status": "error", "message": "「社区垃圾分类督导」在 2026-10-26 已经有一条记录了（3 小时）……"}` |

设计说明：姓名与学号**不作为工具参数**，而是从已绑定的个人账号读取后写入记录——用户不必在每句话里重复身份，模型也没有机会填错姓名。参数校验放在工具内部（日期格式、未来日期、时长范围、重复记录），模型只负责把用户口语里的"今天""三个半小时"解析成结构化参数；校验失败时返回 `error` 与可执行的修正建议，由模型转述。`kind` 允许省略但给了自动判定规则，保证"帮我记一笔军训志愿服务 4 小时"这类说法也能正确落到校内口径。

### 调用链

`query_volunteer_data` → `calc_total_hours` → `export_volunteer_excel`

`calc_hours_by_type`（校内外拆分，可独立调用，也可接在查询之后）

`add_volunteer_record`（录入分支，写入后可立即查询/统计）

`query_open_activities`（活动咨询独立分支，可与时长统计链并行）

模型依据系统提示词与工具描述自主串联这些工具，无需人工编排。六个工具均以结构化 JSON 返回状态（success / error / empty），由模型根据状态决定下一步动作或向用户转述结果。

### 对话示例

| 用户输入 | 模型自主发起的工具调用 |
| --- | --- |
| 帮我统计 10 月每个人的志愿总时长并导出 Excel | `query_volunteer_data(scope="all")` → `calc_total_hours` → `export_volunteer_excel` |
| 我 10 月做了哪些志愿 | `query_volunteer_data(scope="me", start_date="2026-10-01", end_date="2026-10-31")` |

| 我只想看校内的志愿记录 | `query_volunteer_data(scope="me", kind="校内", start_date=..., end_date=...)` |
| 帮我记一笔：今天参加社区垃圾分类督导 3 小时 | `add_volunteer_record(project_name="社区垃圾分类督导", date="2026-10-27", hours=3, kind="校外")` |
| 上周六去敬老院服务了 4 小时，记到我名下 | `add_volunteer_record(project_name="敬老院陪伴服务", date="2026-10-17", hours=4)` |

## 4. 推荐演示话术（现场 4 分钟按这个顺序走）

1. **先绑定账号**（左侧栏选「张三」）— 讲一句："身份只绑一次，后面所有录入都不用再写姓名学号。" 指一下顶部四张卡：**最左边那张深色大卡是累计志愿总时长 15.5 小时**，下方细条显示校内 12.5 / 校外 3.0 的占比，最右边一张才是记录条数。
2. `帮我记一笔：昨天在社区做垃圾分类督导 3 小时` → 看工具日志出现 `add_volunteer_record`，四张 KPI 卡片当场联动：记录 +1 条、校外时长 +3、总时长同步变大。
3. `帮我看看我校内和校外的志愿时长分别是多少，总共多少小时` → 一次 `calc_hours_by_type` 调用同时给出三个口径，体现"数字全部来自工具"。
4. `帮我统计 10 月每个人的志愿总时长，并导出 Excel` → 一次请求里连续出现 `query_volunteer_data → calc_total_hours → export_volunteer_excel` 三次调用，随后自动出堆叠柱状图、侧栏出现下载按钮。
5. **活动中心三级筛选**：在页面底部把「省份」切到四川省 →「城市」切到成都市 →「区县」切到武侯区，面包屑即时显示"共 8 个 · 校内 0 / 校外 8"；再点「↩️ 回到本校」一键回到上海。然后用对话问 `成都武侯区有什么志愿活动`，验证对话与页面用的是同一套数据。
6. **切换账号到李四** — 讲一句："记录、对话、图、导出文件名全部跟着换，旧账号的数据不会残留。"（校内 2.5 / 校外 6.0）

**兜底话术**：若现场网络或接口异常，说 `把 2026 年 9 月到 10 月的记录汇总导出` 复现一次即可；页面所有错误都会以中文提示 + 可修正建议返回，不会白屏。

## 6. 局限与后续规划

### 当前局限

- 数据为内存模拟数据（`st.session_state`），重启即恢复初始样例，未接数据库；录入的记录、绑定的账号与学校只保存在当前会话中。
- 个人账号为**本地会话内绑定**，仅用于把姓名/学号自动带入记录，不是统一身份认证（无密码、无学号校验、无跨设备同步）；换浏览器即需重新绑定。
- 单用户本地应用，未做多用户并发、登录鉴权与会话隔离。
- 仅支持按日期+项目名筛选，暂不支持按姓名、时长区间等复合条件查询（"我的记录"筛选在界面表格层完成）。
- 活动数据为按真实机构与场馆整理的模板 + 本地稳定伪随机生成，非校方或主办方系统实时接口；报名链接指向官方平台首页，具体活动页需在平台内检索。地区维度是真实的（来自开源行政区划数据），活动条目本身是演示内容。
- 高校坐标按城市中位数估算（331 所无公开坐标的高校用所在城市兜底），个别多校区院校的定位可能与实际校区有偏差，仅用于演示距离排序。
- 校外活动按直线距离（Haversine）估算，未接入地图路网导航，实际通勤距离与时间会更长；跨市查询不计算距离。
- 区县重名（如"鼓楼区"分属南京与福州）时按行政区划数据的首个匹配解析，用户可在页面下拉里明确选择。
- 导出工具的文件字节暂存于会话状态，未做历史导出记录管理。
- 模型换算相对时间（"本月""上周"）依赖系统提示注入的当天日期，极端表述可能需要用户补充具体日期。

### 后续扩展规划

1. **数据持久化**：接入 SQLite/云数据库，录入记录、绑定账号与学校长期保存，支持多端登录同步。
2. **统一身份认证**：把"选择/新建账号"换成学校统一身份认证（CAS/OAuth），学号由认证结果下发，杜绝冒名录入。
3. **权限与审批**：志愿时长"提交—审核—归档"流程化，导出操作加确认步骤。
4. **工具扩展**：新增"按姓名查询个人明细""生成月度趋势折线图""发送催报提醒""站内直接报名"等工具。
5. **真实活动源**：对接校团委志愿管理系统与上海志愿者网的项目接口，把演示活动池换成实时抓取，并接入地图路线规划 API 计算真实通勤距离与时间。
6. **部署**：Docker 化部署至服务器，支持更大并发。
