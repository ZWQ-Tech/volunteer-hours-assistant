# ⏱️ 校园志愿时长汇总助手（路径 B）

> 课程：《开源AI技术实践》期末考察项目 · 路径 B
> 一句话场景：把"查志愿记录 → 统计总时长 → 导出 Excel"和"看校内活动 → 找校外附近活动"两条业务，全部交给自然语言对话完成，由通义千问 Tool Calling 驱动。

---

## 1. 项目介绍

校园志愿活动多、记录分散，期末统计"谁的志愿时长够不够"往往靠手工翻 Excel，活动信息又散落在公众号和班级群里。本项目把这套流程封装成一个 **Streamlit Web 应用 + LLM Agent**：

- 用户在对话框说一句"帮我统计 10 月每个人的志愿总时长，并导出 Excel"；
- 通义千问解析意图，自主决定依次调用查询工具、统计工具、导出工具（链式 Tool Call）；
- 页面实时高亮展示每一次工具调用的入参/结果日志，查询后自动生成柱状图，导出的 Excel 直接在网页内点击下载；
- 用户绑定学校后，页面可展示校内志愿活动的实时更新，并按距离推送校园周边的校外活动，同样支持自然语言查询。

工具调用全部通过 Function Calling 协议由模型真实发起；五个业务工具均为本项目自主设计实现。

### 场景说明

| 项目 | 说明 |
| --- | --- |
| 选题 | 志愿服务｜社区志愿活动分配与时长统计 |
| 目标用户 | 校团委/院系志愿者负责人、班级志愿委员 |
| 痛点 | 志愿记录散落在各班表格里，汇总、校对、出报表全靠手工；活动信息分散在公众号与群通知中 |
| 方案价值 | 自然语言一句直达，工具链自动执行，结果可视化、可下载留档；绑定学校后可集中查看校内实时活动与上海全市校外推送，并查看详情、跳转官方报名 |

### 技术栈

| 层 | 技术 | 用途 |
| --- | --- | --- |
| 大模型 | 通义千问（`qwen-plus`，可通过 `.env` 的 `DASHSCOPE_MODEL` 切换为 `qwen-turbo` 等） | 意图理解、Tool Call 决策 |
| 接入方式 | OpenAI 兼容接口（`openai` SDK） | 无缝切换其他兼容模型 |
| Web 框架 | Streamlit | 对话界面、表单、图表、日志分区、活动详情展开 |
| 数据处理 | pandas | 记录筛选、按姓名分组统计 |
| 图表可视化 | plotly.express | 柱状图展示每人累计时长 |
| Excel 导出 | openpyxl | 生成 xlsx 汇总表 |
| 活动推送 | Streamlit 会话态轮询 + Haversine 距离公式 | 校内活动实时刷新、上海全市校外活动按距离排序 |
| 密钥管理 | python-dotenv | `.env` 加载 API Key，不入库 |

### 主要功能特性

1. **个人账号绑定与记录联动**：侧栏顶部可绑定个人账号（内置 4 个演示账号：张三/李四/王五/赵六，也可「新建我的账号」填写姓名+学号+院系）。绑定后顶部状态条显示"我的记录数 / 我的累计时长 / 单次平均时长 / 全员记录数"；页面上方固定两张**只属于本人**的 KPI 卡片——「我的志愿记录总数」「我的累计志愿时长」，**点击记录总数卡片即可展开逐条记录明细**（日期 / 项目 / 时长 / 地点 / 备注），再点「收起明细」收起；后续录入志愿记录只需填活动名称与时长，姓名与学号由账号自动带入，不再重复填写。
   **切换账号时记录同步切换**：两张 KPI 卡片与明细面板、数据表、对话查询结果、统计表、柱状图、导出文件名全部跟着新账号走，且在录入新记录后即时刷新；切换瞬间即清空上一个账号的查询结果与对话上下文，数据表模式为"仅本人"，勾选「显示全部成员的记录」或对助手说"每个人/全员"才切到全员口径（KPI 卡片始终保持本人数据）。
2. **绑定学校**：侧栏可绑定上海杉达学院（金海校区 / 嘉善校区）等院校，内置真实校区地址与经纬度，默认绑定金海校区；绑定后顶部状态条展示"校内活动数 / 上海全市校外活动数 / 覆盖区数 / 最近活动距离"。
3. **活动中心（实时刷新 + 全市推送）**：页面底部分「校内活动」「上海全市校外」两个页签。校内活动按轮询刷新（报名人数递增、新活动推入并高亮 NEW）；校外活动覆盖浦东、黄浦、徐汇、静安、杨浦、长宁、普陀、宝山、松江等区，可按区域下拉筛选、按关键字搜索，并按距校区距离由近到远排序，卡片显示所属区、距离与报名进度。
4. **活动详情与报名入口**：每张卡片下方可展开「活动详情与报名」，查看活动介绍、招募对象、集合信息、联系人、注意事项，并附官方平台报名链接（上海志愿者网 / 上海科技馆 / 上海图书馆 / 中华艺术宫 / 上海市血液中心 / 学校官网），一键跳转报名。
5. **日志分区展示**：独立区域高亮显示每一次工具调用的工具名、入参、状态、结果摘要，与模型对话内容明确区分。
6. **网页内置 Excel 下载按钮**：导出成功后侧栏即时出现下载按钮，一键保存，无需去文件夹找文件。
7. **一键录入志愿记录**：侧栏表单只需「活动名称 + 服务日期 + 时长（+可选地点）」即可写入当前账号名下，既可直接点按钮提交，也可在对话里说"帮我记一笔：今天社区清洁 3 小时"，由模型调用录入工具完成，形成"写入-查询-统计-导出"闭环。
8. **异常容错**：日期格式校验、结束日期不得早于起始日期、未来日期拒绝登记、重复记录提示、单次时长超范围提示、无数据友好提示、未绑定账号/学校时的引导提示、非法区域返回可选项、工具异常统一捕获，程序不崩溃。
9. **自动柱状图**：每次统计成功后，plotly 柱状图自动展示每人累计时长。

## 2. 运行步骤（Windows 可直接复制执行）

```bash
# 1. 进入项目目录
cd volunteer-hours-assistant

# 2. 创建并激活虚拟环境
python -m venv .venv
.venv\Scripts\activate

# 3. 安装依赖
pip install -r requirements.txt

# 4. 配置密钥：复制 .env.example 为 .env，填入你的 DashScope API Key
copy .env.example .env

# 5. 启动
streamlit run app.py
```

启动后浏览器自动打开 `http://localhost:8501`。

使用顺序：① 左侧栏顶部「个人账号」选择演示账号或新建自己的账号并绑定 → ② 在「录入我的志愿记录」里只填活动名称与时长即可记账（默认绑定「上海杉达学院（金海校区）」，可在下方切换院校）→ ③ 页面底部「活动中心」浏览校内活动与上海全市校外活动，展开卡片可看详情并跳转报名 → ④ 在对话框用自然语言发起查询、统计、导出。

## 3. 核心工具参数说明

### 3.1 `query_volunteer_data` —— 按条件查询志愿记录

| 项 | 内容 |
| --- | --- |
| 入参 `start_date` | `string`，必填，格式 `YYYY-MM-DD`，起始日期 |
| 入参 `end_date` | `string`，必填，格式 `YYYY-MM-DD`，结束日期 |
| 入参 `project_name` | `string`，**可选**，志愿项目名称关键字筛选（如"图书馆"） |
| 入参 `scope` | `string`，**可选**，枚举 `me` / `all`，默认 `me`。`me` 只查当前登录账号本人的记录（与页面记录口径一致），`all` 查全部成员；用户说"每个人/全员/全班"时由模型传 `all` |
| 返回（成功） | `{"status": "success", "scope": "me", "owner": "张三（本人）", "count": n, "message": "...", "records": [{姓名, 学号, 志愿项目, 日期, 时长(小时)}, ...]}` |
| 返回（异常） | `{"status": "error", "message": "日期格式不正确..."}` / `{"status": "error", "message": "结束日期早于起始日期..."}` |
| 返回（无数据） | `{"status": "empty", "owner": "张三（本人）", "message": "张三（本人）在该时间范围内没有志愿记录"}` |

参数设计说明：`project_name` 与 `scope` 均为可选参数，扩大模型可用表达空间；日期在工具内部做二次校验，不信任模型输出的格式。`scope` 让"我的记录"与"全员记录"两种业务口径并存——个人账号切换后，默认口径自动跟着变，避免出现"页面显示我的记录、对话却报全班数据"的不一致。

### 3.2 `calc_total_hours` —— 按姓名分组统计累计时长

| 项 | 内容 |
| --- | --- |
| 入参 `records` | `array<object>`，**可选**，来自上一次查询的 `records`；省略时自动使用最近一次查询结果（体现工具链式调用） |
| 返回（成功） | `{"status": "success", "summary": [{姓名, 总时长(小时), 参与次数}], "总计(小时)": x}` |
| 返回（异常） | `{"status": "empty"...}`（无记录可统计）/ `{"status": "error", "message": "缺少字段..."}` |

参数设计说明：`records` 设计为可省略，工具内部直接读取会话中缓存的最近一次查询结果，避免让模型把大数组原样回传导致参数 JSON 被截断；字段缺失、非数值时长均做容错（`fillna(0)`、`to_numeric(errors="coerce")`），统计结果按总时长降序，便于生成排名式回答。

### 3.3 `export_volunteer_excel` —— 导出汇总 Excel

| 项 | 内容 |
| --- | --- |
| 入参 `summary` | `array<object>`，**可选**，来自上一次统计的 `summary`；省略时自动使用最近一次统计结果 |
| 返回（成功） | `{"status": "success", "filename": "志愿时长汇总_20261026_195300.xlsx", "message": "..."}` |
| 返回（异常） | `{"status": "empty"...}`（无可导出数据）/ `{"status": "error", "message": "导出失败：..."}` |

参数设计说明：`summary` 同样可省略，工具内部读取最近一次统计结果，避免大数组回传；生成 xlsx 二进制后写入会话状态，页面侧栏随即出现内置下载按钮；文件名带时间戳避免覆盖。

### 3.4 `query_open_activities` —— 查询校内活动与上海全市校外活动

| 项 | 内容 |
| --- | --- |
| 入参 `scope` | `string`，**可选**，枚举 `all` / `on_campus` / `off_campus`，默认 `all`；用户只问校内就传 `on_campus`，只问校外/上海就传 `off_campus` |
| 入参 `district` | `string`，**可选**，限定上海某个区（如"浦东新区""徐汇区"）；不传则返回上海全市活动 |
| 入参 `keyword` | `string`，**可选**，标题/主办/地点/标签关键字，如"科普""助老""环保" |
| 返回（成功） | `{"status": "success", "school": {...}, "area": "上海全市", "on_campus": [...], "off_campus": [...], "message": "..."}` |
| 返回（未绑定） | `{"status": "error", "message": "尚未绑定学校，请先在左侧绑定学校后再查询活动"}` |
| 返回（区域非法） | `{"status": "error", "message": "未识别区域「火星区」。上海市可选区域：浦东新区、黄浦区……"}` |
| 返回（无匹配） | `{"status": "empty", "message": "在「上海杉达学院（金海校区）」的徐汇区范围内没有找到符合条件的活动"}` |

返回结构说明：每条活动含 `标题 / 主办 / 地点|地址 / 区域 / 日期 / 时间段 / 时长 / 名额 / 已报名 / 剩余名额 / 标签 / 报名链接`，校外活动额外带 `距离km`，列表按距离升序，便于模型直接回答"哪个最近"。

参数设计说明：三个参数全部可选，模型可只传 `scope`，也可以一句话带出"浦东新区有什么科普类活动"这种复合意图；区域名做了归一化（"浦东"→"浦东新区"），非法区域直接返回可选项而不是静默返回空列表；距离由工具内的 Haversine 公式计算，不让模型自己算，避免数值幻觉。未绑定学校时工具主动返回 `error` 引导用户绑定，而不是编造数据。

### 3.5 `add_volunteer_record` —— 为自己录入新的志愿记录

| 项 | 内容 |
| --- | --- |
| 入参 `project_name` | `string`，**必填**，志愿活动名称，如"社区垃圾分类督导" |
| 入参 `hours` | `number`，**必填**，本次时长（小时），如 `3`、`2.5`；超 24 小时会被拒绝 |
| 入参 `date` | `string`，**可选**，`YYYY-MM-DD`；省略则默认当天，未来日期会被拒绝 |
| 入参 `place` | `string`，**可选**，服务地点 |
| 入参 `note` | `string`，**可选**，备注 |
| 返回（成功） | `{"status": "success", "record": {...}, "personal_total": 17.0, "personal_count": 4, "message": "已为 张三（学号 2023001）录入：2026-10-27 社区垃圾分类督导 3 小时……"}` |
| 返回（未绑定） | `{"status": "error", "message": "尚未绑定个人账号。请先在左侧「个人账号」中选择或新建账号并绑定……"}` |
| 返回（重复） | `{"status": "error", "message": "「社区垃圾分类督导」在 2026-10-26 已经有一条记录了（3 小时）……"}` |

设计说明：姓名与学号**不作为工具参数**，而是从已绑定的个人账号读取后写入记录——用户不必在每句话里重复身份，模型也没有机会填错姓名。参数校验放在工具内部（日期格式、未来日期、时长范围、重复记录），模型只负责把用户口语里的"今天""三个半小时"解析成结构化参数；校验失败时返回 `error` 与可执行的修正建议，由模型转述。

### 调用链

`query_volunteer_data` → `calc_total_hours` → `export_volunteer_excel`

`add_volunteer_record`（录入分支，写入后可立即查询/统计）

`query_open_activities`（活动咨询独立分支，可与时长统计链并行）

模型依据系统提示词与工具描述自主串联这些工具，无需人工编排。五个工具均以结构化 JSON 返回状态（success / error / empty），由模型根据状态决定下一步动作或向用户转述结果。

### 对话示例

| 用户输入 | 模型自主发起的工具调用 |
| --- | --- |
| 帮我统计 10 月每个人的志愿总时长并导出 Excel | `query_volunteer_data(scope="all")` → `calc_total_hours` → `export_volunteer_excel` |
| 我 10 月做了哪些志愿 | `query_volunteer_data(scope="me", start_date="2026-10-01", end_date="2026-10-31")` |
| 帮我记一笔：今天参加社区垃圾分类督导 3 小时 | `add_volunteer_record(project_name="社区垃圾分类督导", date="2026-10-27", hours=3)` |
| 上周六去敬老院服务了 4 小时，记到我名下 | `add_volunteer_record(project_name="敬老院陪伴服务", date="2026-10-17", hours=4)` |
| 这周学校有哪些志愿活动可以报名 | `query_open_activities(scope="on_campus")` |
| 上海有哪些科普类的志愿活动 | `query_open_activities(scope="off_campus", keyword="科普")` |
| 浦东新区有什么可以报名的活动 | `query_open_activities(scope="off_campus", district="浦东新区")` |
| 图书馆那个项目我做了多少小时 | `query_volunteer_data(start_date=..., end_date=..., project_name="图书馆", scope="me")` |

## 4. 局限与后续规划

### 当前局限

- 数据为内存模拟数据（`st.session_state`），重启即恢复初始样例，未接数据库；录入的记录、绑定的账号与学校只保存在当前会话中。
- 个人账号为**本地会话内绑定**，仅用于把姓名/学号自动带入记录，不是统一身份认证（无密码、无学号校验、无跨设备同步）；换浏览器即需重新绑定。
- 单用户本地应用，未做多用户并发、登录鉴权与会话隔离。
- 仅支持按日期+项目名筛选，暂不支持按姓名、时长区间等复合条件查询（"我的记录"筛选在界面表格层完成）。
- 活动数据为按真实机构与场馆整理的演示数据 + 本地定时器模拟刷新，非校方或主办方系统实时接口；报名链接指向官方平台首页，具体活动页需在平台内检索。
- 校外活动按直线距离（Haversine）估算，未接入地图路网导航，实际通勤距离与时间会更长。
- 导出工具的文件字节暂存于会话状态，未做历史导出记录管理。
- 模型换算相对时间（"本月""上周"）依赖系统提示注入的当天日期，极端表述可能需要用户补充具体日期。

### 后续扩展规划

1. **数据持久化**：接入 SQLite/云数据库，录入记录、绑定账号与学校长期保存，支持多端登录同步。
2. **统一身份认证**：把"选择/新建账号"换成学校统一身份认证（CAS/OAuth），学号由认证结果下发，杜绝冒名录入。
3. **权限与审批**：志愿时长"提交—审核—归档"流程化，导出操作加确认步骤。
3. **工具扩展**：新增"按姓名查询个人明细""生成月度趋势折线图""发送催报提醒""站内直接报名"等工具。
4. **真实活动源**：对接校团委志愿管理系统与上海志愿者网的项目接口，把演示活动池换成实时抓取，并接入地图路线规划 API 计算真实通勤距离与时间。
5. **部署**：Docker 化部署至服务器，支持更大并发。
